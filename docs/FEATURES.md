# Profile experience features — definitions, scopes, thresholds

All README visuals are static SVG generated by `update-profile` from the SAME view-models (`src/profileos/generators/features.py`).
A visual is hidden when its data is unavailable; nothing is estimated or zero-filled. Status of each item is in `PLAN.md`.

## Profile Signal (`profile-signal.{light,dark}.svg`) — replaces Development Pulse
| Tile | Definition |
|---|---|
| Stars | Sum of stars over public, non-fork repositories published on this profile (profile repo and `publish: false` projects excluded) |
| Contributions | GitHub contribution calendar total, last 12 months (identical scope and dates to the Contribution City) |
| Repositories | The account's public repository count from GitHub (new `profile` dataset; not the featured-project count) |
| Followers | Current follower count (no history is recorded or implied) |
A tile whose source is missing is omitted.

## Building in Public (`BUILDING` marker) — replaces Currently Building + NOW
- **Building / Exploring / Learning**: human-declared in `profile.yml` (`now.building` takes project slugs, which must be published).
- **Recent activity**: derived from public commits (last 30 days), labelled "not a statement of intent". Never shown as Building.
- **Recently shipped**: existing releases / merged PR / meaningful-commit logic, each entry links to GitHub.

## Project Map (`project-map.*.svg`) — replaces the OS-series graph
Nodes: published, public, non-fork projects. Radius: `11 + 9·min(1, ln(1+stars)/ln(51))` (0 stars = 11, ≥50 stars = 20).
Colour: central `CATEGORY_STYLE` tokens, plus a letter code inside every node (readable without colour). Ring = OS-series membership.
Edges: shared GitHub topic (solid) or shared significant language (dashed; a language counts if ≥15% of the bytes of BOTH repos).
README draws each node's strongest 3 edges; `edges` in the model is complete. Layout: deterministic force simulation + box de-overlap.

## Language Bubbles (`language-bubbles.*.svg`) — replaces the language bar
Circle area ∝ share of code bytes (public, non-fork, non-archived repos; same filters as before); top 7 ≥2% + Other. Not a skill measure.

## Contribution City (`contribution-city.*.svg`) — replaces the heatmap in the README
One tile per calendar day. Level 0 = flat ground; level L = 1 + min(3, (count−1)·4 // busiest_day); heights 0/5/10/16/24. Same data and levels as the heatmap model.
Size ceiling 80 KB (worst case, a fully dense year, measures ~58 KB).

## Activity Rhythm (`activity-rhythm.*.svg`)
Contributions by calendar weekday (Mon–Sun) over the same 12-month window; hidden if < 56 days of calendar or < 14 contributions. No hours, no productivity claims.

## Code Pet (`code-pet.*.svg`)
- Mood by active days in the last 7 days (to the fetch day): 0 Resting · 1–2 Warming up · 3–4 Active · 5+ Thriving
- Food by contributions in the last 7 days: 0 No activity · 1–9 Light · 10–24 Fed · 25+ Well fed
- Growth by contributions over the 12-month window: <100 Newborn · 100–399 Growing · 400–799 Young · 800–1499 Adult · 1500+ Veteran
- Growth is a high-water mark stored in `data/cache/pet.json` (real runs only): it can rise, never fall. Rest days never reduce anything.
- Streak: consecutive days with contributions; the fetch day (possibly in progress) is never counted as a miss. With no streak the card shows the longest streak instead.

## Collaboration CTA (`collaboration.*.svg` + Markdown links)
Text from `profile.yml → collaboration`; links only from `links.yml`. No availability promise. `config.yml → pages.url` (empty until Pages is deployed) links the map/city images.

## Marker migration
`PULSE→SIGNAL`, `OS_SERIES→PROJECT_MAP`, `LINKS→CTA`; `CURRENTLY_BUILDING/NOW/RECENTLY_SHIPPED→BUILDING`; missing `LANGUAGE_BUBBLES/CITY/RHYTHM/PET` inserted. In memory, idempotent, applied by `validate` and `build`.


## Layout and motion (second pass)

**Layout.** Cards are published as composites, built from the same view-models and nested into one SVG: a two-column version (880 wide) for desktop and a stacked version (432 wide) for phones, chosen by `<picture>` `min-width: 700px` sources. Columns that end up shorter than their neighbour have their last card stretched, so rows end on one line. Composites: `overview` (signal + commit bars | pet + rhythm), `systems` (map | city + languages), `featured` (project cards, two per row). Every project card, map node and link is also a real Markdown link underneath, because links inside an image are not clickable. Headings live inside marker blocks, so a section with no data leaves no empty heading.

**Motion.** Pet hops and its middle button ticks; signal tiles rise in and the live dot pulses; rhythm bars grow; the city rises in a left-to-right wave; map nodes float and dashed (shared-language) lines flow; language bubbles breathe; the CTA dots and bar pulse. Implemented as CSS keyframes in an SVG `<style>`, validated by `safety.check_css` (class selectors, `@keyframes`, animation/transform/opacity/stroke-dash properties only; no `url()`, `@import`, comments or `<`). Any stylesheet that animates must carry a `prefers-reduced-motion: reduce` override or the build fails. SMIL (`animate`, `set`) stays forbidden.

**Status.** Implemented and fixture-tested (Chromium: animations run, reduced-motion shows the final static state). Not yet verified on github.com: that GitHub serves the `min-width` picture sources and plays CSS animation in README images. If either is not honoured the README still renders correctly (static, stacked-or-wide image).
